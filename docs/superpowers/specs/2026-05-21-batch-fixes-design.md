## Group A: Discussion & AI (`fix/discussion-ai`)

### A1. Markdown Editor Upgrade

**Problem:** `PostForm.tsx` uses raw `<textarea>`; `ThreadCard.tsx` uses `react-markdown` without GFM plugin. Tables, task lists, and other GFM features render poorly.

**Solution:** Replace with `@uiw/react-md-editor`.

- **PostForm.tsx:** Replace `<textarea>` with `MDEditor` component from `@uiw/react-md-editor`. Enable edit/preview/split modes. Keep the existing `maxLength`, `placeholder`, and submit logic.
- **ThreadCard.tsx:** Replace `<ReactMarkdown>` in `PostBody` with `MDEditor.Markdown` component (read-only markdown renderer from the same library). Remove custom `markdownComponents` map — the library handles GFM natively.
- **Styling:** Import `@uiw/react-md-editor/markdown-editor.css`. Override CSS variables to match the project's dark theme (background `#0F0F13`, accent `#FF8C00`, text `#D0D0D0`).
- **Dependencies:** `npm install @uiw/react-md-editor`

### A2. Hide AI Format on AI-Generated Posts

**Problem:** The "AI Format" button appears on all posts, including those already generated by AI (`isAiGenerated === true`). This allows infinite re-format loops.

**Solution:** In `ThreadCard.tsx`, add `&& !post.isAiGenerated` to the AI Format button condition (line 298 and line 449 for replies).

### A3. AI Badge Verification

**Problem:** User reports AI-generated summaries are not marked with "AI" badge.

**Root cause analysis:** The `PostBody` component already renders an "AI" badge when `post.isAiGenerated === true` (line 157-159). The `ai-format` route sets `isAiGenerated: true` on insert (line 157). The GET discussion route selects `isAiGenerated` (line 65). The issue may be that replies to replies (nested AI summaries) are invisible due to A4, making it appear they're not tagged.

**Solution:** Verify the full data flow. If `isAiGenerated` is missing from any response, fix the query. Ensure the badge renders in all visible contexts (thread body, reply body, nested reply body after A4).

### A4. Two-Level Reply Nesting

**Problem:** Clicking "AI" button on a reply creates an AI summary as a child of that reply. The UI only renders one level of replies (`repliesMap.get(thread.id)`). The AI summary is invisible.

**Solution:** In `ThreadCard.tsx` replies section (line 381-502), for each reply, also render its children from `repliesMap`. Add a `NestedReplies` sub-component that renders up to one additional level. The AI-generated reply (with `isAiGenerated === true`) will appear indented under the reply it was generated from.

```tsx
// For each reply, also show nested replies
{repliesMap.get(reply.id)?.map(nested => (
  <div key={nested.id} className="ml-6 pl-3 border-l border-[#FF8C00]/5">
    {/* nested reply rendering */}
  </div>
))}
```

## Group B: UI Quick Fixes (`fix/ui-quick-fixes`)

### B1. Notification Dropdown Position

**Solution:** Change dropdown wrapper div to `className="absolute right-0 mt-2 z-50 min-w-[280px]"`. This anchors it to the right edge of the bell button.

### B2. Recent Activity Clickable Links

## Group C: File System (`feat/file-system`)

### C1. R2 Presigned URL Upload

**Problem:** All file uploads fail with "Network error". Next.js default body size limit (4.5MB) blocks audio files (up to 120MB). Current flow: browser → Next.js API → R2. The Next.js server is a bottleneck.

**Solution:** Direct-to-R2 upload via presigned URLs.

**New API endpoint:** `GET /api/projects/[id]/files/upload-url`
- Authenticated, returns `{ uploadUrl, publicUrl, storageKey, fields }` per file
- Uses `@aws-sdk/s3-request-presigner` with `PutObjectCommand`
- Returns S3 presigned POST URL with 5-minute expiry

**UploadZone.tsx changes:**
- Instead of `FormData` POST to `/api/projects/[id]/files`, call `GET /api/projects/[id]/files/upload-url?name=...&type=...` for each file
- Upload file directly to R2 via `fetch(uploadUrl, { method: "PUT", body: file, headers: { "Content-Type": file.type } })`
- On success, call `POST /api/projects/[id]/files` with JSON body `{ storageKey, name, size, mimeType, folderId }` to create DB record
- Better per-file progress tracking and error messages

**Existing POST /api/projects/[id]/files changes:**
- Accept JSON body with file metadata (not FormData with binary) since R2 upload already happened
- Keep the DB insert + notification logic; remove `uploadFile()` call from this handler

**Storage.ts additions:**
- New `createPresignedUploadUrl(projectId, folderPath, filename, contentType)` function
- Uses `@aws-sdk/s3-request-presigner` `getSignedUrl` with `PutObjectCommand`
- 5-minute URL expiry

### C2. Audio Player Controls

**Problem:** `FileList.tsx` uses raw `HTMLAudioElement` with no visible progress bar, seek, or volume control. Only play/pause button.

**Solution:** Inline player bar + optional modal player.

**Inline Player Bar (FileList.tsx):**
- When audio is playing, expand the table row to show a control bar below the file name
- Controls: play/pause button, current time display, `<input type="range">` progress bar (seekable), total duration display, volume icon + volume slider
- Use the existing `audioRef` for state; add `onTimeUpdate` listener for progress

**AudioPlayerModal.tsx (new component):**
- Larger player in a Modal for focused listening
- Same controls at larger size + file name, format, size display
- Triggered by clicking file name or an expand button
- Uses same underlying Audio element (shared ref or new instance)

**Shared audio hook (optional):** `useAudioPlayer` hook to manage audio state (playing, currentTime, duration, volume, seek) reusable between inline and modal.
